OpenClaw supports custom providers out of the box via models.providers in the config JSON. Ollama exposes an OpenAI-compatible API, so you can add it like this:

{

"models": {

"providers": {

"ollama": {

"baseUrl": "http://localhost:11434/v1",

"api": "openai-chat",

"models": [

{ "id": "llama3.3:latest" },

{ "id": "qwen2.5-coder:32b" }

]

}

}

},

"agents": {

"defaults": {

"model": { "primary": "ollama/qwen2.5-coder:32b" }

}

}

}

If Ollama runs on a different machine, install Tailscale on both and use the Tailscale IP: "baseUrl": "http://100.x.x.x:11434/v1".

With 16GB RAM you can run 7-13B parameter models (Llama 3.3 8B, Qwen 2.5 7B). For better quality, run Ollama on a home machine with a GPU (RTX 3090/4090 can handle 32B+ models) and connect via Tailscale.

Cost tips: OpenRouter gives access to much cheaper models (Gemini Flash). You can also do hybrid: Ollama for routine tasks, cloud API only for complex reasoning.

I did a blog post about this if you want to dive deep in Ollama.

https://clawnest.ai/blog/openclaw-ollama-local-models-guide

I pointed my bot at this thread and said "how would we do this" haha. Wild times. Almost.

Yeah, theoretically you could chain together several AI tools to pull that off. Here's how the pipeline would look:

The concept:

    Script generation — An LLM generates answers to common interview questions tailored to a specific job description and your resume

    Voice cloning — Tools like ElevenLabs or Tortoise TTS clone your voice from sample audio

    Avatar/deepfake video — Something like HeyGen, Synthesia, or open-source tools like SadTalker/Wav2Lip generate a realistic talking-head video of "you" speaking those answers

    Real-time orchestration — For a live interview, you'd need speech-to-text on the interviewer's questions, LLM processing to generate responses, TTS to voice them, and video synthesis — all in near real-time

Where it breaks down practically:

    Latency — Live conversation requires sub-second response times. The full pipeline (transcribe → generate → TTS → video render) would introduce noticeable delays, especially for back-and-forth dialogue

    Uncanny valley — Current real-time deepfake video still has artifacts, especially with varied lighting, head movements, and expressions

    Follow-up questions — Interviewers go off-script, and natural conversation flow is hard to fake without obvious tells

    Screen sharing/live coding — Technical interviews often require demonstrating skills in real time

The real risks:

    Most companies now use tools specifically designed to detect this (like screen recording analysis, liveness checks, or behavioral analysis)

    It's fraud — getting hired this way and being unable to perform the job has led to lawsuits and criminal charges in some cases

    Remote hiring is already tightening verification partly because of this exact concern

The tech is getting closer every month though. The gap between "possible in a lab" and "convincing in a live Zoom call" is shrinking fast. It's one reason a lot of companies are pushing back toward in-person final rounds.

How OpenClaw Might Quietly Kill 80% of Tech Startups

I did not come to this conclusion in a single moment. It crept up on me slowly while browsing Product Hunt, scrolling through Hacker News, and Googling the same startup questions most builders ask at some point. What should I build next. What problem is still unsolved. Where is the opportunity. And that is when it started feeling strange. Most of the ideas looked different on the surface, but underneath they were all the same. Workflows. Dashboards. Humans assisted by software. Nothing truly autonomous.

That is where OpenClaw changes everything.

Agentic AI is not just another tool in the stack. It is a replacement for the stack itself. When software can observe a system, make decisions, take action, and improve without waiting for instructions, entire startup categories stop being companies and start becoming configurations.

Think about legal workflow tools. Startups charging two hundred dollars per user per month just to coordinate paralegal work like document review, summaries, and filings. With OpenClaw, this becomes a group of agents working together. No heavy UI. No fragile integrations. Just outcomes.

The same applies to healthcare admin automation. Clinics pay hundreds every month for billing and compliance software that mostly moves data around. An agent does not need reminders or buttons. It reads, acts, follows up, and reports. End to end.

Even ecommerce tools are not safe. Inventory tracking, dynamic pricing, supplier alerts. Entire micro SaaS businesses exist just to do this one thing. OpenClaw does it continuously without rules hard coded by humans.

While researching all this on Google, I came across another platform called StartupIdeasDB. What stood out was not the ideas themselves but the pattern. Many of them are not bad ideas. They are just fragile ones. The kind that only exist because software could not act on its own before.

This is why I believe a large percentage of tech and micro startups will not survive this shift. Not because founders are lazy or markets are crowded, but because the abstraction they are building on is disappearing. When execution becomes cheap, narrow products lose their value.

The new generation of builders will not ask what SaaS to build. They will ask what entire workflow can be removed. They will not ship tools. They will ship systems.

OpenClaw is not inspiring new startups. It is quietly deciding which ones never need to exist in the first place.
